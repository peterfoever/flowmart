## 一、业务背景

运营已经能够创建 SPU、生成和维护 SKU，但还不能方便地从商品列表中找到需要处理的商品。
希望按名称、编码、类目、品牌、状态和创建时间组合筛选，并分页查看商品摘要。

本卡的列表主体是 **SPU，一条 SPU 只占一条记录**，不是 SKU 列表。

## 二、本期范围和明确约束

1. 新增后台接口 `GET /api/product/admin/spus`，通过 URL query 参数筛选，不使用 GET 请求体。
2. 返回 `R<PageResult<SpuListVO>>`，沿用公共分页结构，不直接返回 Entity 或 IPage。
3. 始终排除已逻辑删除的 SPU；状态未指定时包含草稿、上架、下架。
4. 多个不同筛选条件之间为 AND；名称、类目范围等具体语义按下一节澄清后实现。
5. 默认 `pageNum=1`、`pageSize=20`，页码必须为正数，每页 1～200 条。
6. 非法参数返回 `PARAM_INVALID`，不能忽略非法筛选后退化为查全部。
7. 默认按创建时间倒序；同一创建时间下的次级排序由开发提出，必须保证固定数据集下顺序稳定。
8. 本期只支持这一种固定排序，不接收客户端 SQL 列名或任意排序表达式。
9. 数据库完成筛选、统计和分页；禁止查全表后用 Java 切页，禁止逐条调用 SPU 详情补齐关联名称。
10. 列表不读取商品描述、规格 JSON、轮播图等详情大字段。

本卡不做：SKU 价格区间与数量聚合、SKU 筛选、Redis/ES、库存查询、上下架写接口、批量导入导出。
深分页要求测量和解释；是否引入游标作为后续优化，由实验结果决定，不把新协议强塞入本卡。

## 三、需求澄清：先回答八问

以下保留最初评审问题；已确认的实现契约见本节末尾“澄清结论”。

1. **名称与编码**：`keyword` 只搜索商品名称，还是名称和编码都搜？名称使用包含还是前缀匹配？独立 `spuCode` 如何匹配？首尾空白、纯空白、`%`、`_` 和转义字符如何处理？SQL 参数绑定和 LIKE 通配符语义是两个不同问题。
2. **类目范围**：选择非叶子类目时，仅查该节点还是包含后代？如果输入的类目不存在、已删除或禁用，报错还是空列表？`categoryId=0` 能否作为“全部”的约定，还是必须不传？说明界面如何选择全部。
3. **品牌范围**：未传品牌默认不筛选，如何单独筛选“无品牌商品”？若同时提供品牌 ID 和无品牌条件，拒绝还是设优先级？品牌禁用、删除或不存在如何处理？筛选与详情名称展示要分别考虑。
4. **时间区间**：创建时间筛选采用哪种格式、时区、边界（含不含端点）？只传一端允许吗？开始晚于或等于结束怎么处理？运营选“某一天”怎样完整覆盖毫秒级数据？
5. **分页与输入边界**：参数省略、显式空字符串、非数字、0、负数、pageSize=201 分别如何处理？请求超出最后一页时，`total` 和 `records` 各是什么？极大页码的 offset 如何安全计算和约束？
6. **关联名称缺失**：SPU 有效，但关联类目/品牌已删除或缺失，商品是否继续显示？`categoryName`/`brandName` 返回 null、占位文案还是历史名称？当前系统没有名称快照，不得假定能返回删除前名称。无品牌与品牌失效怎样区分？
7. **排序与并发变化**：多条 SPU 的创建时间相同，如何稳定分页？请求下一页前新增/修改了商品，还能保证跨请求绝不重复或遗漏吗？本期保证什么、不保证什么？COUNT 与列表分别查询期间数据变化的响应口径是什么？
8. **查询与性能**：如何在不随记录数增加查询次数的前提下返回关联名称？选联表还是本页批量补齐，为什么？如何让 COUNT 与列表使用一致筛选条件，避免遗漏筛选或关联导致总数错误？先验证哪些现有索引，不要直接给每个条件加索引。

### 澄清结论

按开发提交的 FM-005 技术方案确认：

1. `keyword` 仅对名称做包含匹配；`spuCode` 精确匹配。均 trim，纯空白视为未传。LIKE 先转义 `!`，再转义 `%`、`_`，使用 `ESCAPE '!'`；SQL 使用参数绑定。长度上限分别128、64，按原始输入校验。
2. 类目包含自身及所有有效后代，递归排除已删除节点；指定根类目不存在/已删除返回 `PARAM_INVALID`，禁用仍允许筛选。根校验后子树为空直接返回 `total=0, records=[]`，不能丢弃类目条件。
3. 品牌不存在/已删除返回 `PARAM_INVALID`，禁用允许查询。`noBrand=true` 仅查 `brand_id IS NULL`，与 `brandId` 冲突；false 或省略不限制。ID 必须为正数，不支持0、-1、NONE等哨兵值。
4. 时间按 Asia/Shanghai 业务约定解释为本地日期时间，不做额外 UTC 转换；严格接受 `yyyy-MM-dd HH:mm:ss`，左闭右开，允许单端，空白视为未传。两端都有时必须 from < to。部署仍需核对运行环境时区与现有数据口径。
5. 默认1页/20条，每页1～200。显式空分页、非数字、越界值返回 `PARAM_INVALID`；页码由 Integer 绑定限制上限，offset 先转 long 再乘。超页保留 COUNT 总数并返回空数组，跳过列表查询。
6. 使用 LEFT JOIN，关联逻辑删除条件放 ON，主表逻辑删除条件放 WHERE。原始名称允许 null；后端另填 `categoryText`/`brandText`，区分有效名称、类目已失效、无品牌、品牌已失效。不逐条查详情。
7. 固定 `created_at DESC, id DESC`。固定数据集下顺序稳定，不保证跨请求无重复/遗漏；COUNT 与列表共享条件但不保证读取时刻一致，列表为空时仍保留 COUNT 结果。
8. COUNT 仅查 SPU，列表按类目/品牌主键联表，公共 WHERE 复用；不读大字段、不联 SKU、不新增缓存。查询次数不随本页商品数增长，实际性能仍需 MySQL 执行计划验证。

## 四、接口与对象草案

### 4.1 请求

已确认字段如下；详细语义见第三节。

| 字段 | 建议类型 | 约束或待定点 |
|---|---|---|
| pageNum | Integer | 默认1，范围1～Integer.MAX_VALUE；显式空值非法 |
| pageSize | Integer | 默认20，范围1～200 |
| keyword | String | 最长128，trim 后名称包含匹配，纯空白不筛选 |
| spuCode | String | 最长64，trim 后精确匹配，与 keyword 组合为 AND |
| categoryId | Long | 指定时正数，存在且未删除；包含自身及有效后代 |
| brandId | Long | 指定时正数，存在且未删除；禁用允许 |
| noBrand | Boolean | true 仅查无品牌且与 brandId 互斥；false/省略不限制 |
| status | Integer | 只允许0草稿、1上架、2下架；不传查全部有效SPU |
| createdFrom / createdTo | String | yyyy-MM-dd HH:mm:ss，Asia/Shanghai，左闭右开，可单端 |

无筛选示例：`GET /api/product/admin/spus?pageNum=1&pageSize=20`。
组合示例：`GET /api/product/admin/spus?pageNum=1&pageSize=20&status=0&noBrand=true&keyword=手机`。
GET 参数由客户端做 URL 编码，不放在请求体中。无匹配结果的 `data` 为：

```json
{"pageNum":1,"pageSize":20,"total":0,"records":[]}
```

非法参数返回统一 `R`：`code=10001, success=false`，message 描述错误；HTTP状态沿用项目约定。

### 4.2 返回

`data` 为公共结构：`pageNum`、`pageSize`、`total`、`records`。
每条 `SpuListVO` 建议包含：

```text
id, spuCode, name, mainImageUrl,
categoryId, categoryName, brandId, brandName,
status, statusText, version, createdAt, updatedAt
```

ID 沿用现有接口表示方式。`records` 无数据时为 `[]`，不是 null。
不返回 `description`、`specs`、`carouselImages`、`deleted` 或未定义的库存/价格字段。

## 五、已有代码与需要注意的边界

- 可复用 `flowmart-common/.../result/PageQuery.java` 和 `PageResult.java`。
- PageQuery 的 `@Min/@Max` 没有同时声明 `@NotNull`；不能仅凭默认值认定显式空参数一定安全，需做 HTTP 绑定测试。若调整公共类，检查其他调用方兼容性。
- 公共分页插件已配置，但插件最大值为500；FM-005 的接口上限是200，不能只靠插件限制。
- 品牌接口使用 `page/size`，本卡使用公共 `pageNum/pageSize`；不要顺便破坏品牌接口契约。
- `PageResult.empty` 会把 total 设为0；判断是否适用于“查到总数但请求页无记录”的情况。
- `SpuStatus` 是商品状态定义来源。已有实体注释写成“启用/禁用”，实现本卡时注意不要沿用该错误语义。
- 可参考 ProductSpuMapper、SpuConverter 和现有详情接口，但不要用逐条查询详情组装列表。
- V5 已有 `uk_spu_code`、`idx_category_deleted`、`idx_brand_deleted`、`idx_deleted_status_created`。先检查执行计划；确需新索引时使用下一个空闲 Flyway 版本，不修改 V5。
- 自定义 SQL 必须自己检查逻辑删除条件；检查关联过滤放置位置是否会意外丢失 SPU。

> 起始日期：2026-08-04（周二）
> 目标：12 周后具备独立承接需求、编写需求/技术文档、交付可上线代码、操作测试与生产环境的能力
> 节奏：每工作日 1 张需求卡，4-6 小时；周末机动（补欠账 / 做周复盘）

## 一、这套训练在练什么

很多人写了三年 CRUD 还是初级，卡点从来不是「会不会写代码」，而是这四件事：

| 能力 | 初级的样子 | 中级的样子 | 本训练怎么练 |
|---|---|---|---|
| **需求能力** | 等着别人把需求嚼碎了喂给你 | 能把一句话业务诉求拆成可实现的方案，能识别出需求里的坑并反推产品 | 每张需求卡都刻意留了模糊点和陷阱，你要先写「需求澄清」再动手 |
| **交付能力** | 功能能跑就算完 | 边界、并发、幂等、回滚、监控都考虑到了 | 每张卡都有验收标准 + Code Review 清单，不过关不算完成 |
| **工程能力** | 代码堆在 Controller 里 | 分层清晰、可测试、可扩展、有文档 | 强制 PR 流程 + CI 卡口 + 单测覆盖率门槛 |
| **环境能力** | 只会在 IDE 里 F5 | 会发布、会看日志、会排查线上问题、会回滚 | dev/test/prod 三套真实环境，每周至少一次完整发布演练 |

**最重要的一条规则**：本训练里我扮演的是**产品经理 + 技术负责人 + Code Reviewer**，不是代跑腿的。
需求卡我出、方案我评审、代码我 Review，但**业务代码你自己写**。你可以随时问我「这里该怎么做」，
但不要说「你帮我写完」—— 那样你只会得到一个仓库，得不到能力。

## 五、每日工作流（必须严格执行，这就是真实工作节奏）

```
09:30  【站会】在当天需求卡下写：昨天做完什么 / 今天做什么 / 有什么阻塞
09:40  【需求评审】读需求卡 → 写「需求澄清」→ 我扮演产品经理答疑
10:00  【技术方案】表结构 + 接口定义 + 关键流程，写进需求卡的方案区
       ⚠️ 超过 2 小时的需求，方案必须先过评审再动手。方案错了，代码写得再好也白搭
10:30  【开发】从 develop 切 feature 分支，小步提交
15:00  【自测】单元测试 + 接口自测，跑通验收标准里的每一条
16:00  【提 PR】填 PR 模板 → 我做 Code Review → 你改 → 合入 develop
17:00  【提测】发布到 test 环境，写发布单，验证
17:30  【收尾】更新需求卡状态，记录今天踩的坑
```

## 六、完成标准（一张卡什么时候算 Done）

一张需求卡必须**同时**满足以下 7 条才算 Done —— 少一条都不算：

- [ ] 需求卡里的「验收标准」逐条勾选通过
- [ ] 代码已合入 `develop`，PR 已通过 Review
- [ ] 核心业务逻辑有单元测试，`mvn test` 全绿
- [ ] CI 流水线绿灯
- [ ] 接口文档（Knife4j）能正常打开且描述完整
- [ ] 已发布到 test 环境并自验通过
- [ ] 需求卡底部写了「踩坑记录」（哪怕写"无"，也要主动想一遍）

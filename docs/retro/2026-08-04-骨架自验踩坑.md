# 复盘 · 骨架自验踩坑 · 2026-08-04

> 这不是训练卡，是搭骨架时真实踩到的坑。四个问题**全部编译通过、单测通过**，
> 只在实际启动和调用时才暴露。FM-010（故障演练）会重新拿出来用。

---

## 坑 1 · `mvn -pl X -am spring-boot:run` 在父 POM 上执行

**现象**：应用起不来，日志停在一堆 `Downloading from central`，没有任何报错。

**根因**：`-am`（also make）会把被选模块的依赖一并选中，其中包括 `packaging=pom` 的父模块。
`spring-boot:run` 作为 CLI 目标会在**每个**被选中的模块上执行，于是先在父模块上跑，直接失败。

**修正**：
```bash
mvn install -DskipTests                                    # 让下游拿到 common 的最新产物
mvn -pl flowmart-bootstrap spring-boot:run -Dspring-boot.run.profiles=dev
```

**举一反三**：`-am` 用于 `compile` / `test` / `package` 没问题，但不适用于 `run`、`spring-boot:build-image`
这类只能作用于单个可执行模块的目标。

## 坑 2 · 后台启动进程被父 shell 带走

**现象**：命令返回"启动成功"，几秒后进程消失。

**根因**：命令写成了 `mvn spring-boot:run > log 2>&1 &` + `echo`。父 shell 执行完 `echo` 立即退出，
子进程随之被回收。

**举一反三**：在 CI、部署脚本里后台拉起服务，要用 `nohup` / `setsid` / `systemd` / 容器托管，
而不是裸 `&`。真实环境里这类问题表现为「部署脚本跑完了，服务却没起来」。

---

## 坑 3 · 健康检查写松了 ⭐️ 最值得记住的一条

**现象**：判活脚本报告"应用已就绪"，实际接口全部返回空。

**根因**：
```bash
curl -s -m 2 localhost:8080/actuator/health >/dev/null 2>&1   # 只看退出码
```
沙箱把 curl 路由到了 HTTP 代理，代理回不到本机 localhost，返回 **502 Bad Gateway + Content-Length: 0**。
502 对 curl 来说是一次**成功的 HTTP 事务**，退出码为 0 —— 判活条件因此误判。

**修正**：判活必须校验响应内容，不能只看退出码：
```bash
curl -s --noproxy '*' -m 2 http://127.0.0.1:8080/actuator/health | grep -q '"status":"UP"'
```

**为什么这条最重要**：这正是 W12 灰度发布演练要面对的问题。如果 K8s 的 readiness 探针
或 Docker 的 HEALTHCHECK 是这么写的，会出现**容器显示健康、流量已经打进来、但实际全是错误响应**
的情况 —— 而且监控大盘上一片绿。这是生产事故里最难排查的一类：**你的观测系统在骗你**。

> 检查一下本项目 `Dockerfile` 和 `deploy/*/docker-compose.yml` 里的 healthcheck：
> 目前用的是 `wget -qO- .../health/readiness`。想一想：它够严吗？
> （提示：`wget` 对 4xx/5xx 会返回非 0，比 `curl -s` 好，但仍没校验响应体内容。
> 这是留给你在 W12 改进的点。）

## 坑 4 · 两个配置各自都对，组合起来出错

**现象**：`/doc.html` 返回 404，接口文档打不开。

**根因**：`application.yml` 里设了 `spring.web.resources.add-mappings: false`。
- 初衷：关掉静态资源映射，让未匹配请求抛 `NoHandlerFoundException`，走统一异常处理返回 `R` 结构 ✅
- 副作用：Knife4j 的 `/doc.html` 本身就是静态资源，被一并关掉 ❌

**修正**（没有二选一，而是换了接住 404 的位置）：
- 恢复静态资源映射
- 在 `GlobalExceptionHandler` 增加 `NoResourceFoundException`（Spring 6.1+）分支

保留静态映射后，未匹配请求会先落到 `ResourceHttpRequestHandler`，抛的是 `NoResourceFoundException`
而非 `NoHandlerFoundException` —— **两个分支都要保留**。

见 PR #1。
